# Full User Input Validation & Sanitization Input Matrix

Last Updated: 2026-07-04 Europe/Brussels

## Purpose

This is the active remediation matrix required by `full-input-validation-sanitization-plan.md`. Implementation has already started in several slices, so this file is no longer a planning-only scaffold. Future implementation should keep high-risk rows current before editing the matching seam, and broad DTO/UI convergence should not continue until the relevant rows have owners, threat models, release priority, decision status, and regression tests.

Senior CTO correction for the next implementation pass: storage remains protected by the completed rows below, but storage is not the default next lane. New work should pick one high-risk API/Application, BFF, or Blazor row; complete that row's inventory; then implement and verify the smallest slice. Audit-only work does not count as progress.

Decision status values:

- `Pending inventory` — row is seeded but incomplete.
- `Needs contract decision` — blocked by `full-input-validation-sanitization-contract-decisions.md`.
- `Ready for slice` — enough information exists to implement in the named slice.
- `Deferred with rationale` — not in current release scope.

## Current Next-Slice Priority

1. Blazor event/session/organization form validation and server-error mapping rows.
2. Email dispatch admin semantic tenant-B masking and raw provider/log leakage coverage.
3. Idempotency and cross-cutting header residuals: idempotency-key, tenant-hint, and forwarded-host validation.
4. Remaining BFF trust-boundary rows only when the matrix identifies an uncovered browser-controlled header, cookie, continuation path, antiforgery, or diagnostics seam.
5. Remaining public/detail route-ID families only when a row identifies an uncovered resource-oracle risk.
