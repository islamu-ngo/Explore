# Context: Blazor Feature Parity

## Key Files
This section lists the key files that will be created or modified during this task.

### New Files
- `Explore.Blazor.Client/Pages/Admin/Categories.razor`
- `Explore.Blazor.Client/Pages/Admin/Tags.razor`
- `Explore.Blazor.Client/Pages/Admin/Locations.razor`
- `Explore.Blazor.Client/Components/Event/EventSessionManager.razor`
- `Explore.Blazor.Client/Components/Event/CreateSessionDialog.razor`
- `Explore.Blazor.Client/Components/Event/EditSessionDialog.razor`
- `Explore.Blazor.Client/Components/Event/RegistrationManagerDialog.razor`

### Modified Files
- `Explore.Blazor.Client/Pages/Event/EventDetail.razor` (to integrate `EventSessionManager`)
- `Explore.Blazor.Client/Pages/Event/EventRegistrationsDialog.razor` (to be replaced or enhanced by `RegistrationManagerDialog`)
- `Explore.Blazor.Client/Layout/NavMenu.razor` (to add links to new admin pages)

## Decisions
- **Component-based approach:** For features like session management, a new component (`EventSessionManager`) will be created and embedded in the `EventDetail` page. This is preferred over adding more complexity to the already large `EventDetail` page.
- **Dialogs for CRUD:** Consistent with the existing UI, dialogs will be used for creating and editing sessions, categories, tags, and locations.
- **Admin pages:** New pages will be created under `/Admin` for managing core data. Access to these pages will be restricted to users with the "Admin" role.

## Dependencies
- The `EventApiClient` generated by NSwag is assumed to be up-to-date with the latest API. If the API changes, the client will need to be regenerated.
- The Cerbos authorization policies are assumed to be correctly configured on the backend to handle permissions for the new features.
