# API Changelog

## 2026-07-30

- Additive deletion-conflict contract for API version `0.1`: `DELETE /api/eventday/{id}` and `DELETE /api/eventsession/{id}` now return typed `409 Conflict` ProblemDetails when a published ticket entitlement references the schedule target. Successful deletion remains `204 No Content`, missing targets remain `404`, and generated clients now surface the conflict response instead of treating a guarded no-op as success.
- Setup rate-limit reliability correction for API version `0.1`: authenticated setup-secret-gated `PATCH /api/instanceonboarding/profile` and `POST /api/instanceonboarding/complete` requests retain the configured five-per-60-second fixed-window protection but now use a separate IP partition from anonymous setup-secret attempts. Legitimate validation and provider setup traffic can no longer exhaust the final instance-claim budget; anonymous and setup-secret-authenticated provider routes remain in the shared anonymous IP partition.
- Reliability fix for API version `0.1`: concurrent `POST /api/events/{eventId}/ticketing/draft` and `POST /api/events/{eventId}/ticketing/draft:clone` attempts that collide on catalog-version uniqueness, plus duplicate capacity-pool name races, now return retryable `409 Conflict` with `event_ticketing_concurrency_conflict` instead of `500`; clients should reload ticketing state and retry.
- Breaking Event pricing correction for API version `0.1`: `EventDto`, `EventListDto`, and generated client models no longer expose the legacy scalar `Event.Price` or `Event.CurrencyCode`, and EventSession contracts no longer expose `EventSession.Price`. The persistence model removes the matching Event and EventSession `price` and `currency_code` columns without a compatibility field or decimal fallback. Published Event reads instead expose nullable `ticketPriceSummary`, derived from the published `EventTicketCatalogVersion`, with `summaryCode`, nullable `currencyCode`, `currencyMinorUnitDigits`, and `fromAmountMinor`. Clients must regenerate from `schemas/openapi_islamu-event.json` and render the summary rather than treating an Event or session scalar as pricing authority.
