# White-Labeling

White-labeling changes presentation. It does not transfer platform, directory, payment, tax, provider, or legal responsibility.

## Customizable presentation

Depending on delegated scope, operators can govern:

* tenant, organization, and group branding;
* navigation;
* footer templates and link groups;
* social links and copyright;
* approved public-experience settings.

Instance governance locks retain required elements while allowing safe tenant customization. Verify the current HAL links before presenting edit controls.

## Accountability identity

Visual branding is not legal identity. Public pages preserve directory-operator and platform-operator identity as distinct disclosure resources. Payment operator/provider responsibility remains separate again.

If required tenant public-disclosure identity is unavailable, the footer fails closed with `503 tenant_identity_unavailable`. A logo, display name, or organization brand is not used as a fallback.

## Operational workflow

1. Establish who owns the tenant and public domain.
2. Configure required accountability identities before visual branding.
3. Apply delegated theme, navigation, and footer changes.
4. Verify governance-locked disclosures cannot be removed.
5. Test public pages on every custom domain and responsive breakpoint.
6. Record recovery for accidental bulk or template changes.

Do not publish claims that branding makes an instance official, certified, compliant, or endorsed. Keep operator and provider responsibility visible in public copy.
