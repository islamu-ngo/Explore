# Events & Ticketing

ISLAMU Event keeps event content, registration, payment, admission, and check-in as distinct authorities. This section explains each lifecycle and the boundaries operators must preserve.

## In this section

* [Modular Event Aspects](modular-event-aspects.md) — typed Islamic and technology event/session data and module gating.
* [Custom Properties](custom-properties.md) — governed long-tail data, exposure ceilings, use grants, retirement, and purge.
* [Ticketing & Check-In](ticketing-and-check-in.md) — registration versus admission, protected credentials, recovery, and online gates.
* [Paid Events & Payouts](paid-events-and-payouts.md) — organizer-direct Stripe Connect, reconciliation, refunds, and responsibility limits.

Before publishing a paid or controlled-entry event, verify module policy, registration, provider-confirmed payment/refund state, admission issuance, credential recovery, and exact-target check-in. Current HAL links govern every operator action.
