# Security & Identity

Authentication, authorization, tenant selection, and privacy erasure are separate authorities. Each fails closed; none silently substitutes for another.

## In this section

* [Authentication](authentication.md) — Keycloak, BFF sessions, direct API credentials, and linked AT Protocol sign-in.
* [Authorization](authorization.md) — Cerbos or local RBAC, resource checks, and HAL action authority.
* [Multi-Tenancy](multi-tenancy.md) — deployment mode, host resolution, persistence filters, and scoped administration.
* [Privacy Erasure](privacy-erasure.md) — anti-resurrection fencing, receipt status, provider cleanup, and recovery topology.

## Claim boundary

These pages describe implemented platform behavior, not security, privacy, accessibility, compliance, or religious certification. Adopters remain responsible for threat modeling, provider agreements, legal assessment, incident response, retention, data residency, vulnerability management, and operational controls.
