# v0.1.0 - First Public Release (Beta)
**Released:** TBD

## Summary
The first publicly-available release of the **ISLAMU Event Platform** — a multi-tenant, federated event discovery system built with .NET 10, Clean Architecture, and enterprise-grade security. This version represents the **MVP baseline** ready for beta testing and early adopter feedback, featuring complete event management, organization workflows, advanced filtering with modular aspects, HATEOAS REST API, and a full Blazor frontend.

**⚠️ Pre-1.0 Notice**: Major version zero (0.y.z) indicates initial development. The public API may change at any time and should not be considered stable. This release is intended for beta testing, early adopters, and feedback gathering.

---

## 🎯 Platform Overview

### What is ISLAMU Event?
A **culturally-aware event discovery platform** designed for Muslim communities and tech meetups, enabling:
- **Event discovery** with advanced filtering (age, gender, madhab, skill level, location, language)
- **Two-tier verification system** (user-submitted vs. verified organizations)
- **Multi-tenant SaaS** architecture (single-tenant and multi-tenant deployment modes)
- **Modular event types** (Islamic events module, Tech events module) with per-tenant enablement
- **Federation readiness** (ATProto/ActivityPub data models — Phase 1 complete, protocol endpoints planned)

### Technology Stack
- **Runtime**: .NET 10.0
- **Architecture**: Clean Architecture + CQRS (MediatR)
- **Frontend**: Blazor Server + WebAssembly (InteractiveAuto hybrid rendering)
- **UI Components**: MudBlazor (Material Design)
- **Database**: PostgreSQL 18 + PostGIS (spatial queries)
- **Authentication**: Keycloak (OIDC/OAuth 2.0) with Backend-for-Frontend (BFF) pattern
- **Authorization**: Cerbos (Policy Decision Point) + ASP.NET Core
- **Secrets Management**: Infisical (with environment variable fallback)
- **API Documentation**: Scalar + Swagger/NSwag
- **Observability**: Serilog + OpenTelemetry (Prometheus + Loki + Grafana)
- **Orchestration**: .NET Aspire (development), Docker (production)

## 🚀 Core Features

### 1. Event Management System
**Complete event lifecycle management with advanced capabilities:**

- **Event Creation & Editing**: Rich event forms with title, subtitle, description, type, format, status, pricing
- **Event Sessions**: Multiple sessions per event with date/time, location, speakers, agenda items
- **Event Registration**: RSVP system with approval workflow, registration limits, waitlist support
- **Event Discovery**: Public event listing with search, filtering, sorting, and pagination
- **Event Types**: Workshop, Lecture, Social, Conference, Seminar, Training, Networking, Fundraiser, Hackathon
- **Event Formats**: In-Person, Online, Hybrid
- **Event Status**: Draft, Published, Canceled, Archived
- **Visibility Control**: Public, Private, Draft-Only
- **Session Management**: Multiple sessions with speakers, languages, agenda breakdowns
- **Advanced Query System**: 33 query parameters via `EventQuerySpecification` fluent builder:
  - Core filters: Title search, type, format, status, date range, audience age/gender
  - Islamic aspect filters: Gender mode, reference prayer, Quran recitation, Islamic primary language
  - Tech aspect filters: Skill level, tech stack tag, coding competition, hackathon, requires laptop
  - Subquery filters: Category IDs, include/exclude tag IDs (AND/OR), location, language, registration mode
  - JSONB filters: metadataJsonContains, metadataJsonKeyExists
  - Sorting: Date, title, views, createdAt

### 2. Organization Management
**Verified organization workflows with member roles:**

- **Organization Creation**: Registration form with approval workflow (Open/Approval Required/Invite Only policies)
- **Organization Profiles**: Name, description, website, logo, social links, verification status
- **Member Management**: Invite members, assign roles (Owner, Admin, Editor, Viewer), update permissions
- **Role-Based Access**: Fine-grained permissions per organization role
- **Organization Reviews**: User ratings and reviews for verified organizations
- **Organization Positions**: Job title lookup for member profiles

### 3. Multi-Tenancy & Admin Hierarchy
**Enterprise SaaS architecture with flexible deployment modes:**

- **Deployment Modes**:
  - **Single-Tenant**: Multi-tenancy disabled, feels like traditional app (TenantId = Default)
  - **Multi-Tenant (SaaS)**: Multiple isolated organizations, subdomain-based routing
- **Tenant Management**: Isolated workspaces with custom branding, navigation links, settings
- **Tenant Resolution**: Header (`X-Tenant-Id`) → JWT claim → Subdomain → Path segment → Default
- **Admin Hierarchy**:
  - **Instance Admins**: System-level configuration (deployment mode, modules, federation, S3, SMTP)
  - **Tenant Admins**: Tenant-level settings (policies, member management, branding)
  - **Organization Admins**: Organization-level operations (events, members, reviews)
- **Cascading Configuration**: Instance → Tenant → Feature override hierarchy with lock/unlock mechanism
- **Module Governance**: System-level gates for module availability (Islamic, Tech) across all tenants

### 4. Modular Event Aspects
**Plugin-style event extensions with per-tenant enablement:**

- **Islamic Events Module** (`EventIslamicAspect`):
  - **Gender Segregation Mode**: Male-only, Female-only, Segregated, Mixed
  - **Madhab Targeting**: Hanafi, Maliki, Shafi'i, Hanbali
  - **Prayer Time Scheduling**: Event times relative to prayer times (liturgical temporal engine)
  - **Audience Filtering**: Age ranges (Children, Teens, Adults, Seniors), Gender designation
- **Tech Events Module** (`EventTechAspect`):
  - **Skill Level**: Beginner, Intermediate, Advanced, Expert
  - **Tech Stack**: Technologies used (e.g., .NET, JavaScript, Python, Docker)
  - **Session Format**: Hands-on, Lecture, Workshop, Q&A
- **Module-Conditional Queries**: Aspect filters only applied when module enabled for tenant
- **Module Service**: `IModuleService` for runtime module availability checking

### 5. Security & Authentication
**Enterprise-grade security with BFF pattern and fine-grained authorization:**

- **Backend-for-Frontend (BFF)**: Blazor Server proxies all API requests
  - Tokens **never** exposed to browser JavaScript
  - Secure HttpOnly, SameSite=Strict cookies
  - YARP reverse proxy forwards `/api/*` requests with Bearer tokens
- **Authentication**: Keycloak (OIDC/OAuth 2.0)
  - Authorization Code flow with PKCE
  - Claims mapping with fallback: `sub` → `nameidentifier` → `sid`
  - Token refresh handling
- **Authorization**:
  - **Endpoint-Level**: `GET = [AllowAnonymous]`, `Write = [Authorize]`, `Admin = [Authorize(Roles="Admin")]`
  - **Resource-Level**: Cerbos Policy Decision Point (PDP) for fine-grained checks
    - `[CerbosAuthorize("event", CerbosPermissionAction.Update)]` attribute on commands
    - `AuthorizationBehavior` MediatR pipeline enforces policies before handler execution
    - YAML policy definitions in `cerbos/policies/` (tenant_settings, organization, instance_settings)
    - Derived roles (e.g., "owner" when `userId == resource.ownerId`)
    - Batch Cerbos checks for HATEOAS link filtering
  - **Link-Level**: `HateoasAuthorizationEvaluator` filters visible actions in HAL+JSON responses
- **Secrets Management**: Infisical provider with health checks, auto-refresh, audit logging, environment variable fallback

### 6. REST API (Level 3 - HATEOAS)
**Hypermedia-driven API with HAL+JSON:**

- **43 REST Controllers** covering all domain entities
- **HATEOAS Implementation**:
  - HAL+JSON format (`application/hal+json`)
  - 18 link policies (Event, Organization, User, Actor, Session, Registration, TenantSettings, etc.)
  - `HateoasLinkGenerator` central service with fluent `LinkDefinition` API
  - `ResourceAssemblerBase<T>` for consistent resource assembly
  - `PreferHeaderMiddleware` for content negotiation (JSON vs HAL)
  - Authorization-aware link filtering — clients only see permitted actions
- **API Documentation**: Scalar + Swagger with OpenAPI 3.0 specs
  - `[EndpointSummary]` and `[EndpointDescription]` on all endpoints
  - `[ProducesResponseType]` for success/failure codes
- **NSwag Client Generation**: Auto-generated `EventApiClient` for Blazor frontend
- **Response Compression**: Brotli + Gzip for optimized payloads

### 12. Caching Strategy (Multi-Level)
**Optimized performance with hybrid caching:**

- **Output Caching**: Response-level caching with named policies:
  - `LookupData` — 1-hour expiration (reference data)
  - `ListData` — 30-second expiration (paginated lists)
  - `DetailData` — 60-second expiration (individual records)
- **HybridCache** (.NET 9+): L1 in-memory (5-minute local) + optional L2 distributed
  - 10MB payload limit, 512-character key limit, 30-minute default expiration
- **Cache Invalidation**: Tag-based invalidation via `OutputCacheInvalidationService`
- **Query Specification Caching**: `ToCacheKeySuffix()` for specification-based keys

## 🏗️ Architecture & Design

### Clean Architecture + CQRS
**4-layer separation with strict dependency rules:**

```
Presentation Layer (Explore.API, Explore.Blazor)
    ↓ depends on
Application Layer (Explore.Application)
    ↓ depends on
Domain Layer (Explore.Domain) ← no external dependencies
    ↑ implemented by
Infrastructure Layer (Explore.Persistence, Explore.Infrastructure)
```

- **Domain Layer**: 62 entities, 18 enums, 3 core interfaces (ITenantEntity, IAuditableEntity, ISoftDeletable)
- **Application Layer**: 48 feature modules, CQRS handlers (MediatR), DTOs with FluentValidation
- **Infrastructure Layer**: EF Core repositories, Keycloak integration, Cerbos service, Infisical provider, S3 storage, SMTP email
- **Presentation Layer**: 43 REST controllers, 44 Blazor pages

### Domain Model Highlights
**Triple Interface Pattern on all entities:**
- **ITenantEntity**: `TenantId` for multi-tenant isolation
- **IAuditableEntity**: `CreatedAt`, `CreatedBy`, `UpdatedAt`, `UpdatedBy`
- **ISoftDeletable**: `IsDeleted`, `DeletedAt`, `DeletedBy` (soft delete with full audit trail)

**Key Entities**:
- Event aggregate: `Event`, `EventSession`, `EventSessionSpeaker`, `EventSessionAgendaItem`, `EventRegistration`
- Event aspects: `EventIslamicAspect`, `EventTechAspect` (module-conditional)
- Organization: `Organization`, `OrganizationMember`, `OrganizationReview`
- Identity: `User`, `Actor`, `ActorKeyStore`
- Lookups: 18+ reference tables (EventType, Category, Tag, Madhab, Language, Location, etc.)
- Federation: `AtprotoRecord`, `IndexedDid`, `SyncState`
- Settings: `TenantSetting`, `AppSetting`, `ConfigurationChangeLog`

### Repository Pattern
- **GenericRepository<T, TId>**: Base repository with CRUD + soft delete
- **Specification Pattern**: `IQuerySpecification<T>` for complex queries
- **EF Core Optimizations**:
  - `AsNoTracking()` for simple read-only queries
  - `AsNoTrackingWithIdentityResolution()` for complex queries with shared navigation properties
- **Named Query Filters** (EF Core 10):
  - `"Tenant"` — Always-active tenant isolation
  - `"SoftDelete"` — Can be selectively bypassed with `IgnoreQueryFilter("SoftDelete")`

### Authorization Pipeline
**Three-level authorization enforcement:**

1. **Endpoint-Level**: `[AllowAnonymous]` / `[Authorize]` / `[Authorize(Roles="Admin")]`
2. **Resource-Level**: MediatR `AuthorizationBehavior` → Cerbos policy checks before handler execution
3. **Link-Level**: `HateoasAuthorizationEvaluator` → Batch Cerbos checks filter visible actions in HAL responses

### BFF Security Model
**No tokens in browser JavaScript:**

```
Browser (Blazor WASM)
    ↓ HTTPS session cookie (HttpOnly, Secure, SameSite=Strict)
Blazor Server (BFF)
    ↓ HTTPS Bearer token (JWT)
API (JWT validation)
```

- `Explore.Blazor` (Server) manages Keycloak OIDC flow, stores tokens server-side
- `Explore.Blazor.Client` (WASM) sends session cookie automatically
- YARP proxy attaches JWT to `/api/*` requests transparently

## 🎓 Getting Started

### Prerequisites
- .NET 10 SDK
- Docker Desktop (for Keycloak, PostgreSQL, MinIO)
- PostgreSQL 18+ with PostGIS extension
- Node.js 20+ (for NSwag client generation)

### Quick Start (Development)
```bash
# Clone repository
git clone https://github.com/islamu/explore.git
cd explore

# Start infrastructure with Docker Compose
docker compose up -d keycloak postgres minio

# Run database migrations
dotnet ef database update --project Event.MigrationService

# Start API
dotnet run --project Explore.API

# Start Blazor (separate terminal)
dotnet run --project Explore.Blazor

# Access application
# Blazor: https://localhost:7002
# API: https://localhost:7039
# Scalar: https://localhost:7039/scalar/v1
```

### Quick Start (Production)
```bash
# Build Docker images
docker build -t explore-api -f Explore.API/Dockerfile .
docker build -t explore-blazor -f Explore.Blazor/Dockerfile .

# Run with Docker Compose
docker compose -f docker-compose.prod.yml up -d

# Access application
# Blazor: https://your-domain.com
# API: https://api.your-domain.com
```
